Hoocode Single View

One transcript mode: each tool call is one row, and a click on the row (or Enter on a focused row) shows its full output. Every pane, card and picker follows one grammar. Both work in dark and light, from 40 to 120+ columns.

This is the final design pass over v3. The spec is spec-v4.md, the review is review-v3.md. Before frames show current code: the 80- and 100-column frames follow the goldens, and the other widths follow the same layout rules. Tool rows in the After frames are computed by the cut-order algorithm itself, so every row on this page fits its width.

What changed since v3

  • The width rule is one ordered algorithm. The ladder is computed from it, not drawn by hand. The target never drops, and a reason narrower than 12 columns drops instead.
  • Failed reasons are dim, so target reason reads apart. Red stays on ⊗ and exit N.
  • Settings keeps Tool output 800 lines · 32 KB. Those caps truncate what the model sees. Only the View leaf goes.
  • Pinned status reuses the real bar: scrolled 43–61 of 78 · ↓ 3 new. While a turn runs the hint says G live, because esc there also stops the turn.
  • esc on a focused block only clears the focus. It never stops a turn.
  • The detail splits at 100 columns, as the code does (v3 said 120). Collapsed thinking keeps today's first-sentence line.
  • Frames are column-accurate (prose and status at column 1, blank rows per tui.md). Split detail columns line up, and every hint uses ink keys and dim verbs.
  • The live demo streams: elapsed time and the tail line update, the call settles, a new row arrives, and ↓ N new counts it while pinned.
  • Facts corrected: resend already exists, the quit keys are k and l, the attach glyph is settled by UI-1, WebFetch leads with ~N tokens.
  • Decisions cut from 25 rows to 9 real choices.
First fix: frozen rows (confirmed by reading the code)

Past the newest 50 calls, blocks freeze. In ToolChainComponent::peek_rows (crates/hoocode-code-tui-widgets/src/tool_chain.rs:374), step_parts() captures the block and releases its result. Then mark(), facts() and is_error() (lines 383 to 389) read None: every frozen row draws a dim running ● with no facts, and a failed row loses its red ⊗, on every render. In a one-row design the row is the mark plus the facts, so P1 starts by saving an unstyled row snapshot at freeze().

Also found by reading: frozen blocks ignore a theme change (invalidate returns early, tool_execution.rs:1458). The snapshot fixes their headers too.

1. One transcript mode

Today a tool call has three views, outline, peek and full, set by toolOutputView and cycled with ctrl+x o. v4 drops them. Every block starts as one row. Its output opens in place, one block at a time, and ctrl+x o now opens or closes them all.

Keys and states

click, enter
Toggle a block. A click in a live view pins it first, with the row kept where it was. Enter acts only on a focused row; with none, it still means back to live.
ctrl+x o
Expand every block, or collapse all when all are open. Replaces the view cycle. O and p are unbound.
ctrl+x u
Focus the newest block, and pin the view. While live, printable keys type into the prompt, so this is the way in.
{ } y esc
Pinned, over an empty prompt: move the focus, copy the block's raw output from the agent's messages, clear the focus. Esc with a focused block never stops a turn.
● ◉ ⊗
Done (green), running (accent; only the elapsed time moves), failed (red ⊗ and exit N, reason dim). Stopped is a dim ⊗. The shape carries the state without colour.

2. Per tool: row, facts and the cut order

Row: gutter, mark, bold tool name, target, two spaces, dim facts. One line, never wrapped. When a row is too wide, the steps run in order: (1) secondary facts drop, right to left. (2) The target shortens to its minimum: a path drops whole leading directories and keeps the file name, and a command cuts at a word. (3) A failed row's reason cuts at a word, keeping 12 or more columns. (4) Otherwise the reason drops, and the target takes the space back. Primary facts never drop. Each terminal keeps its last column for the scrollbar.

The ladder: one row at 40, 60, 80 and 120

At 80 the failed row keeps the whole reason and shortens the command, because step 2 runs before step 3. At 40 a 12-column reason does not fit, so it drops and the command grows back. The red exit 1 still says it failed.

3. Pane grammar and tokens

One grammar for every picker, pane, card and dialog. Every colour is a theme token, so dark and light come for free.

Title
A chip with the noun (accent; yellow only when the agent waits on you), then a dim /command, then dim facts. Facts drop at 40.
Rows
Indent 3. The selected row: paneSel fill, accent ›, ink text, no bold. Secondary cells dim. One fact per row that compares rows.
Glyph rows
Only the glyph carries colour: ● ok, ◉ accent, ○ dim, ⊗ red (dim when cancelled).
Detail
At 100+, a right column at a fixed column. From 60 to 99, stacked under the list. Under 60, three rows, then ….
Input row
▏ filter on the surface colour. Only the selected row carries ›.
Hint row
Last. key verb, key ink, verb dim, from the keymap. At most four items, then f1 more where it has a list. The move item drops first. enter and esc never drop.
Verbs
move pick open close back skip stay, plus the action word. cancel only stops a running flow.
Yellow
Blocking only: permission, question, MCP trust, elicitation, auth needed. Working ◉ is accent everywhere.
Mouse
No clicks in panes in v1 (decision 8).
Monochrome
Light borders with the title in the border. The selection keeps › and bold or reverse video.

4. Panes

The ten key panes, Before and After, at the width chosen above. The fourteen minor panes have an After at 40 and at 100. At other widths they show the nearer one, and the caption says which.

S1 Settings · opened by /settings

  • The Tool output row stays, minus its View leaf: it now reads 800 lines · 32 KB, the caps that truncate what the model gets (decision 7).
  • The detail splits at 100 columns, at a fixed column. Below that it stacks. Below 60 it shrinks to three rows.
  • The filter row uses ▏, so only the selected row carries ›. Units say tokens, never tok/turn.

S2 Task panel · opened by ctrl+x g

  • Only the glyph is coloured. ◉ is accent, not yellow. Done text is dim, and a cancelled row is dim throughout.
  • The tab strip shows the tab in view and +N tabs at narrow widths, with ctrl+x g pinned to the right.

S3 Question (ask options) · opened by the agent asks

  • The chip is yellow because the agent waits for you. The question is ink, and 1 of 2 is dim.
  • At 40 the description moves to its own row, indented 6, so labels stay aligned.

S4 Permission card · opened by a gated call

  • The hint keeps four items at every width: 1–3 pick · y yes · n no · e edit fits in 40. a still highlights row 2.
  • At 40 the command wraps to two rows, and the always-row continues at indent 6.

S6 Model picker · opened by /model

  • in use sits on the row. The detail labels are dim and the values are ink, at a fixed column.

S8 Sessions picker · opened by /resume

  • The colour swatch goes. Each row shows the name and the age. The hint keeps four items, plus f1 more.
  • Ages normalised to 2h ago in both frames (the goldens read 56y ago from the mock clock).

S10 Attached subagent (ctrl+x n) · opened by ctrl+x n

  • The header takes › and a bold name (UI-1). esc back sits at the right. ◉ is accent.
  • While attached, the status line drops esc stop, because esc goes back.

S12 Slash-command menu · opened by typing /

  • The selected row is not bold (overturns tui.md line 80). Descriptions stay under 60 characters.

S16 Status line · opened by always the last row

  • No view name anywhere. The right side drops cost, then session, then the word context, then the model.
  • Pinned while a turn runs, the bar says G live: esc there also stops the turn. The last row is the hint while a block has focus.

S17 Composer · opened by the prompt row

  • A pasted image becomes an atomic [image #1 · clipboard.png] marker, like the paste marker. The send payload keeps the temp path.

Minor panes

S5 Quit with jobs

Accent chip: you asked, nothing waits on you. Jobs are ◉ accent. The keys are the card's real k and l.

S7 Scoped models

on is ink, off is dim. Green means done, so it no longer stands in for a switch.

S9 Subagent runs (/agents)

Glyph, name, description and state word. The state word takes the glyph colour. No dispatch id.

S11 @file completion

A pmenu on the pane fill, directly above the prompt. The selected row is › on the fill, not bold.

S13 Keys and which-key

Keys are ink in both. The duplicate Show keyboard shortcuts row goes. Which-key lists the new o and u.

S14 Fork

The explanation moves into the detail. The filter marker is ▏, so one › shows.

S15 Log in

docks goes. esc cancel appears only while a login runs.

S19 Notices and tips

A warning's first row is ink bold, not yellow. Info is dim. The tip loses ★.

S20 Model error

Only the glyph is red. The resend already exists; only the hint text changes, with the key from the keymap.

S21 Compaction notice

A toggle block like any other. A shrink says saved N, a grow says up N.

S22 MCP status

Glyph rows. auth needed is yellow because it waits on you. The config stays in .agents.

S23 Text output blocks

One helper for /session, /perf, /changelog and the rest: bold heading, dim labels, ink values, no blank rows inside.

S24 Transient rows

One row above the prompt at a time, in this order: retry, leader, search, warning.
